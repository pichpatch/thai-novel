One-Photo Publication Workflow

The production workflow now centers on fast story packaging for YouTube. A new story starts with a non-rendered in/ep0.json story bible, one shared poster for every YouTube post in the story, and one OpenAI/Codex-generated image per source episode.

Business Rules

  • in/ep0.json is a story bible and prompt handoff for the user and other AI agents, including open_ai_instruction for pre-generating all images.
  • Each renderable epNN.json source episode should contain exactly one chapter and one image.
  • Each episode image should be a poster-like key visual that summarizes that episode, shows related visible characters and the dominant setting/event, and contains exactly one readable title set and no duplicate title layer, logo, signature, random text, or watermark.
  • Automatic publishing groups contain at most 10 source episodes per MP4.
  • A grouped video's YouTube description must include the short description for every included source episode.
  • A grouped video's YouTube description must also include a character relationship tree for the included episodes: prior relationship state, what changes in the group, latest relationship status, and small details for characters who appear.
  • The whole-story poster is stored at novels/poster/background.png, summarizes the whole story, and is reused for every YouTube post for the story.
  • The poster is not the only in-video image. The video shows the channel image during welcome, then switches to the current episode image when each episode starts.
  • The grouped clip sequence is: welcome narration with channel image, spoken episode title, episode image with episode narration, then repeat spoken episode title plus episode image for each next episode.

Onboarding Notes

The first action for a new story is filling ep0.json. After that, generate the poster and episode images, then write ep01.json, ep02.json, and so on from the template.
